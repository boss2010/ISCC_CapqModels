# تحويل الوارد إلى EF — المرحلة الأولى

## المنفذ

- Scaffold فعلي باستخدام EF Core 9.0.4 لعدد 30 جدولًا وView واحد من القاعدة المتصلة بالمشروع.
- الموديلات الجديدة في `EF/Imports/Entities`، والسياق المستقل `EF/Imports/ImportDbContext.cs`؛ لم يتم استبدال موديلات الشاشات الأخرى أو تضمين بيانات الاتصال في الملفات المولدة.
- ربط السياق باستخدام `AddPooledDbContextFactory`؛ كل عملية قراءة متوازية تحصل على سياق مستقل. لا يشارك أكثر من استعلام متزامن نفس السياق.
- تحويل قائمة الطلبات واللجان، رأس الطلب والأصناف واللوطات والعينات، دمج بيانات العينات المحفوظة، حالات سير العمل والصلاحيات والاختيارات الأساسية والتحقق من نطاق السحب إلى EF/LINQ مع `AsNoTracking`.
- تحديد بيانات اللجان المسموح بها أولًا، وجلب الأعمدة اللازمة فقط، دون تحميل محتويات المرفقات الثنائية.
- التحقق من هوية اللوطات باستعلام واحد بدل استعلام لكل لوط.
- قراءة `PackagesCount` كنص طبقًا لنوعه الحقيقي في القاعدة وتحويله إلى decimal عند العرض؛ القيم مثل `796.8` محفوظة دون تقريب.

## حدود هذه المرحلة

عمليات الحفظ الحالية التي تنسق نتيجة الفحص، إنشاء لجنة السحب، التسلسلات والباركودات وموقف الحجر ما زالت تستخدم SQL ومعاملاتها وأقفالها الحالية. كذلك بقيت قراءة المعالجات وبعض استعلامات نتائج المساعد والحجر على SQL. هذه مرحلة قراءة وتحقيق بيانات قابلة للنشر، وليست تحويلًا كاملًا لكل SQL في المشروع إلى LINQ. اختبارات هذه المرحلة لا تسجل نتائج حقيقية أو تعدل باركودات.

قراءة أسماء الأعضاء من `dbPrivilage` تتم عبر `Database.SqlQuery` بمعاملات EF، لأن جدول المستخدمين في قاعدة منفصلة. يجب أن يظل حساب التطبيق قادرًا على قراءة هذا الجدول كما في الإصدار السابق.

## سكربت قاعدة البيانات

`PlantMobile/Sql/20260922_ImportEfIndexes.sql`

السكربت يضيف عمود `SampleQuantityUnit` فقط إذا كان غير موجود، ويضيف 13 فهرسًا لدعم الربط والتصفية والحالات. لا يحول `PackagesCount` ولا يعدل سجلات التشغيل. كل إنشاء مشروط بعدم وجود اسم الفهرس؛ يمكن إعادة تشغيل السكربت بعد توقفه. الفهارس الإضافية تستهلك مساحة وتضيف تكلفة محدودة لعمليات الكتابة.

الفحص الفعلي وجد أن جداول اللجان والأعضاء والنتائج والعينات ومرفقاتها ومواقف اللوطات والتأكيدات تملك فهارس المفتاح الأساسي فقط. جدول بيانات الطلب يملك فهارس أخرى؛ الفهرس المقترح عليه يغطي آخر سجل واسم المفوض. تمت مراجعة الأعمدة مع المخطط الفعلي وفحص صياغة السكربت باستخدام `SET PARSEONLY ON` دون تطبيقه. لم تُقَس سرعة الفهارس بعد إنشائها، ولم يُختبر تطبيق السكربت مرتين على نسخة اختبار بعد.

## الاختبار

من جذر المشروع، مع إعداد `PlantMobile/appsettings.json` لقاعدة الاختبار المناسبة:

```powershell
dotnet build tests/ImportEfRegression/ImportEfRegression.csproj -p:NuGetAudit=false -o tests/ImportEfRegression/bin/verification
dotnet tests/ImportEfRegression/bin/verification/ImportEfRegression.dll
```

الاختبار التكاملـي يعتمد على بيانات الحالة الأصلية: المستخدم 354، الطلب 331324، اللجنة 155292، وتاريخ 2026-09-22. يقارن كل حقول القوائم مع SQL القديم، يختبر رجوع شاشة الفحص دون Redirect، الكميات العشرية، نطاق السحب الجزئي والكلي، وقراءة عينة موجودة. لا يُشغَّل على قاعدة خالية دون تجهيز بيانات مكافئة. يوجد SQL القديم في `ImportRequestsSql` كمرجع للمقارنة.

القياس المحلي الأول قبل تنفيذ فهارس السكربت: القائمة القديمة نحو 6.4 ثانية، EF نحو 5.2 ثانية في أول تشغيل ونحو 4 ثوانٍ بعد التهيئة؛ لجان الطلب 331324 نحو 0.54 ثانية مقابل 0.31 ثانية. هذه قياسات حالة واحدة على البيئة المحلية، وليست ضمانًا لأداء السيرفر أو قياسًا لأثر الفهارس.

## النشر على السيرفر

1. شغّل سكربت SQL على القاعدة التي يشير إليها `DBConnection` في السيرفر خلال فترة هادئة؛ إنشاء الفهارس يحتاج أقفالًا وصلاحيات ALTER. احتفظ بنسخة الإصدار الحالي للرجوع.
2. أنشئ نشرًا جديدًا، وليس نسخ ملفات C# أو DLL واحد:

```powershell
dotnet publish PlantMobile/PlantMobile.csproj -c Release -o publish
```

3. انقل ناتج النشر كاملًا، بما فيه `PlantMobile.dll` و`EF.dll` و`ViewModels.dll` وملفات `wwwroot`، مع الحفاظ على إعدادات اتصال السيرفر وتخزين المرفقات الخاص به.
4. أعد تشغيل التطبيق أو App Pool، واختبر الدخول من الهاتف وفتح نفس طلب الفحص، وراجع `Logs` إذا ظهر خطأ.

الـScaffold وحده لا يتطلب Migration أو إنشاء قاعدة جديدة. لا يوجد `EnsureCreated` أو `Migrate` أو تنفيذ DDL تلقائي عند بدء التطبيق. الرجوع للإصدار السابق لا يتطلب حذف الفهارس الجديدة أو عمود الوحدة.

## إعادة توليد الموديلات لاحقًا

```powershell
dotnet tool install dotnet-ef --version 9.0.4 --tool-path .tools
# بعد بناء مشروع البداية بنجاح:
./tools/Scaffold-ImportModel.ps1 -Refresh
```

السكربت يستخدم `Name=ConnectionStrings:DBConnection` و`--no-onconfiguring`. راجع فروق الملفات الناتجة قبل النشر. تحذيرات علاقات الجداول غير المختارة متوقعة لأن هذا سياق خاص بالوارد؛ أعمدة المفاتيح نفسها تبقى في الموديلات. لا تضف منطقًا يدويًا داخل الملفات المولدة، بل في ملفات partial مستقلة أو خدمات القراءة.

## شاشة الدخول للموبايل

أصبحت صفحة HTML عربية مستقلة تحتوي على viewport وملف CSS بإصدار لمنع استخدام نسخة مخبأة قديمة. تمت مراجعتها على 320×568 و390×844 و768×1024 و1440×900، مع حقل إدخال بحجم 16px وزر قابل للوصول بدون تمرير أفقي، واختبار ارتفاع صغير يحاكي مساحة لوحة المفاتيح. إظهار لوحة مفاتيح حقيقية على جهاز فعلي لم يُختبر.
